# Web 产品与服务候选配置

适用于浏览器或应用界面连接后端能力的产品。默认候选为一个可部署应用加清晰业务模块；独立 API 或多服务须说明组织/伸缩/隔离收益。

| 决策 | 候选及判断依据 | 产物 |
| --- | --- | --- |
| 渲染 | 静态、服务端、客户端或混合；由 SEO、交互和离线需求选择 | 首屏与交互预算、缓存和错误行为 |
| 后端 | 统一全栈或独立服务；由团队技能、客户端数量和发布边界选择 | 模块与部署边界 |
| 持久化 | 关系模型作为结构化业务候选；其他存储由查询和一致性需求证明 | 约束、索引、迁移、恢复 |
| 身份权限 | 复用组织身份或成熟方案，应用可信层做授权 | 用户/角色/租户权限矩阵 |
| UI 系统 | 现有合适组件库或小型自建组件集 | 语义 tokens、状态与无障碍验收 |
| 部署 | 托管平台、容器或已有组织平台 | 环境、秘密、发布与观测入口 |

```text
src/
  modules/                  # 按业务能力组织
  shared/                   # 已验证的共享能力
tests/                      # 按项目选择的测试层级
docs/                       # 项目材料
```

如果确需 monorepo：`apps/` 放可部署应用，`packages/` 放版本/职责明确的共享包；边界通过包依赖与 CI 检查落实。不要先建空的 `microservices/`、`event-bus/` 等目录。

第一条纵向切片：从一个用户操作穿过 UI、授权、领域规则与数据写入，验证成功、失败、重复操作、观测和部署。随后用结果调整设计，不一次性生成完整业务系统。
