# 跨项目共享资产目录

此目录提供跨项目发现与复用的统一入口。当前只有本框架这个真实资产；不要把规划中的组件列为已经可用。维护者在组织内建立仓库后补稳定 URL，项目采用/退出时更新消费者和兼容信息。

| 资产 ID | 能力与边界 | 当前版本 | Owner | 来源 | 消费者/状态 |
| --- | --- | --- | --- | --- | --- |
| ASSET-FRAMEWORK | 项目实施规范、材料模板、初始化与升级比较 | [VERSION](../../VERSION) | 框架维护者角色，待指定实际 owner | [文档入口](../README.md) | 初始基线；真实试点待登记 |

## 新资产登记字段

使用一页记录：ID、名称、解决的问题、不适用范围、领域边界、owner/支持联系人、源仓库与许可证、版本/包/契约地址、支持窗口、真实消费者、依赖与运行约束、兼容/迁移/弃用策略、验证与发布证据。对应项目保留一个指回本目录的地址即可，不双写全部登记内容。

## 项目联通约定

- 项目 ID 和领域边界独立命名；业务词汇明确语义后再共享类型。
- 每项数据有唯一写入责任方；其他项目通过契约访问，减少越过边界直读表。
- 身份/租户、时间/单位、错误语义、追踪 ID、API/事件版本在接口处对齐。
- 消费者记录采用版本、负责人和升级窗口；破坏性变化明确通知责任与迁移证据。
- 复用选择记录为“直接采用 / 适配 / 自建及原因”，不要把所有共性都抽成中心服务。

治理流程见 [复用与升级](../handbook/reuse-and-upgrades.md)；发现现有资产不再满足条件时，保留弃用与替代指引。
