# 代理指令互操作研究

本研究支持初始化框架中的代理协作规范。采用“共享指令单一来源、工具适配薄层、按任务读取专业规范、实际运行验证”的设计。产品行为按 2026-09-20 的官方文档核验；下文将已核实事实与本框架的设计建议分开。

## 1. 名称与职责

| 文件 | 本框架用途 | 使用边界 |
| --- | --- | --- |
| `AGENTS.md` | 跨工具共享的项目工作约定与导航入口 | 使用大写复数文件名；不要依赖 `Agent.md`、`aagent.md` 等变体被自动识别 |
| `CLAUDE.md` | Claude Code 适配入口 | 共享内容通过导入复用；只增加已确认的 Claude 专属差异 |
| `.github/copilot-instructions.md` | GitHub Copilot 适配入口 | 按实际使用的 Chat、CLI、IDE、云代理、代码审查分别验收 |
| `CLOUD.md` | 可选的云基础设施、环境、部署导航 | 普通项目文档，不视为代理指令入口；具体部署规范仍有唯一权威来源 |
| `README.md` | 人类入口、项目目的、启动与使用说明 | 供代理导航参考，但不替代指令文件和运行配置 |

`AGENTS.md` 的官方格式是普通 Markdown，没有必填字段或固定章节。它约定承载项目背景、构建测试、编码和安全提示；格式本身不保证每种工具拥有相同的加载器。依据：[AGENTS.md 官方说明](https://agents.md/)。

用户提到的 `Cloud.md` 可能指 `CLAUDE.md`，也可能确实指云部署文档。本框架同时明确两者职责，避免靠名称猜测产生错误配置。

## 2. 已核验的加载规则

### Codex

Codex 在启动时建立指令链：先查 `CODEX_HOME` 的全局指令，再从项目根目录走到当前工作目录；每级依次选择 `AGENTS.override.md`、`AGENTS.md`、已配置的备用名称，最多一份。链按根到叶组合，较近指令覆盖较早指导；默认总量上限为 32 KiB。它不会因此预先遍历整个仓库的子目录。依据：[OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

**本框架的应用：**根指令要求修改某目录前检查沿途的局部指令；长期团队规范使用 `AGENTS.md`。临时 override 应被列入排查项，不能默认为所有工具支持。命令执行中临时切换目录也不能被当作重新加载启动指令的证据。

### Claude Code

官方当前文档注明 v2.1.277 起可原生读取 `AGENTS.md`；默认在工作目录或祖先存在项目 `CLAUDE.md`、`.claude/CLAUDE.md` 或 `CLAUDE.local.md` 时优先走 CLAUDE 路径。第三方提供商、功能开关等会限制原生支持；`AGENTS.override.md` 不在其读取范围。`CLAUDE.md` 可用 `@AGENTS.md` 导入，路径相对导入文件，最多四层；子目录 CLAUDE 在读取该目录文件时加载。导入内容会进入上下文，普通路径引用不等于导入。依据：[Claude Code memory](https://code.claude.com/docs/en/memory)。

**本框架的应用：**保留短 CLAUDE 导入层以覆盖不同运行环境；在拥有局部 AGENTS 的目录中配置同级适配或明确读取步骤。不要把“后加载”概括成所有工具都能确定性解决自然语言冲突，直接消除冲突更可靠。

### GitHub Copilot

Copilot 的仓库级入口是 `.github/copilot-instructions.md`，路径指令位于 `.github/instructions/**/*.instructions.md`，用 YAML `applyTo` 指定 glob。适用的路径指令与仓库指令可同时加载；支持代理指令的场景中，就近 `AGENTS.md` 优先。依据：[GitHub 仓库指令设置](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions)。

GitHub 明确列有功能支持矩阵：GitHub.com Chat、VS Code Chat、云代理与代码审查不完全相同。例如，GitHub.com Chat 的支持清单包括仓库级指令，但不包括 AGENTS；不能把某个代理的行为推断给所有 Copilot 功能。依据：[Copilot 指令支持矩阵](https://docs.github.com/en/copilot/reference/custom-instructions-support)。

在 GitHub 文档描述的自定义指令优先级中，路径指令高于仓库级文件，后者又高于 AGENTS 等代理指令；相关指令仍一起提供给模型。依据：[Copilot 自定义指令概念](https://docs.github.com/en/copilot/concepts/prompting/response-customization)。

**本框架的应用：**适配文件避免重写共享规则；只有工具无法读取共享源时，才通过受控生成增加必要的自包含规则投影，并验证无漂移。普通 Markdown 链接不是通用导入机制，对不具备文件读取能力的 Chat，链接本身不能提供文件内容。

**文档不一致记录：**当前 GitHub 支持矩阵的代码审查项只列 AGENTS，而[代码审查使用说明](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review)还提到 CLAUDE、GEMINI 和 REVIEW。基础框架依赖共同确认的 AGENTS 与 Copilot 仓库入口；其他入口留待目标环境实测，不把这一差异包装成确定的通用保证。

## 3. 共享源与薄适配的设计

以下是本框架建议，属于本地设计决策，不声称是所有厂商强制标准。

```text
AGENTS.md                         共享工作约定与有条件导航
CLAUDE.md                         导入同级 AGENTS.md
.github/copilot-instructions.md   Copilot 导航与必要适配
docs/                             可按需阅读的完整规范
<module>/AGENTS.md                该模块的真实差异（需要时才添加）
<module>/CLAUDE.md                局部 AGENTS 的 Claude 适配（需要时添加）
```

根 AGENTS 建议控制在约 60–120 行，作为本框架维护目标而非产品限制。只放所有任务都需要的信息：仓库目的、当前技术栈与命令入口、操作边界、分支与 PR 约定、完成证据、按需导航。实际命令优先指向仓库已经存在且已验证的脚本；没有应用代码的参考仓库应如实只列文档校验命令。

按需导航用“触发条件 + 必须读取的来源 + 完成标准”表达。例如：

| 触发条件 | 应读取的内容 | 读取后的完成标准 |
| --- | --- | --- |
| 改变用户可见行为 | 对应 PRD、功能 spec、验收条件 | 确认问题范围、非目标与可观测结果 |
| 修改 UI 或交互 | 交互规范、设计系统、页面状态定义 | 覆盖键盘、加载、空态、错误、权限和响应式场景 |
| 修改接口或数据模型 | API 契约、领域模型、相关 ADR | 列出兼容性、迁移和消费者影响 |
| 修改生产运行方式 | 发布、可观测性、回滚与事故流程 | 明确部署证据和恢复路径 |
| 修改代理指令 | 代理协作规范及本研究 | 检查真实加载路径和共享源漂移 |

导航应链接实际存在的具体文件，初始化后通过链接校验验证。研究报告、历史 ADR、所有技术规范不应被统一 `@` 导入到根上下文；模板也不应成为全仓自动生效的指令集合。

最小 CLAUDE 适配内容：

```markdown
@AGENTS.md
```

这是 Claude 的导入语法示例。若增加专属说明，写在导入之后并说明适用环境；不要把相同写法直接复制到 Copilot 文件后假设会被展开。采用普通文件导入也避免将跨平台复制流程绑定到符号链接。

模块指令仅记录相对于根规范的差异，例如该模块的测试入口、边界与特殊风险。框架要求编辑前同时理解根约定与适用的局部约定，不用层级覆盖来隐藏矛盾。人类授权、平台权限和上级运行指令不能被仓库 Markdown 自行提升或取消。

## 4. 从真实仓库借鉴什么

AGENTS 格式仓库本身的指令文件，用少量条目解释该站点的开发服务器注意事项、依赖同步、编码约定和命令。其价值在于记录容易踩坑的项目事实，而非复述所有工程常识。依据：[agentsmd/agents.md 的固定版本 AGENTS.md](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/AGENTS.md)。

我们借鉴“具体操作 + 原因 + 正确执行入口”，不复制其 Next.js 开发会话限制到其他技术栈。例如某仓库对开发构建目录的限制，不能变成所有项目都禁止生产构建的通则。

同仓库 README 示例把测试与 CI 位置、包级命令、PR 约定放在一起，体现让代理尽快定位可执行检查的思路。依据：[固定版本 README](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/README.md)。本框架采纳可定位、可执行、可验证三点，具体命令和检查范围仍由当前项目决定。

## 5. 安全边界、上下文与执行证据

OpenAI 官方将沙箱的技术边界与审批策略区分：前者限制可访问资源，后者控制何时请求授权。依据：[OpenAI sandbox 文档](https://learn.chatgpt.com/docs/sandboxing)。Claude 官方也说明其持久指令属于上下文而非强制配置，并单独提供权限与隔离机制。依据：[Claude memory](https://code.claude.com/docs/en/memory)、[Claude Code security](https://code.claude.com/docs/en/security)。

据此，本框架要求：

1. **权限靠运行环境落地。**生产写入、发布、凭据与网络访问由平台权限、受限身份、环境保护和组织审批控制；不要把“禁止访问”一句话当成已实施隔离。
2. **授权保持连续。**读取、计划、可逆本地修改和验证在已授权范围内自主进行。外部副作用遵循明确授权和实际平台策略；不为同一已授权步骤反复请求确认。
3. **外部内容作为资料。**Issue、网页、日志、依赖文件中的指令性文字需按来源判断；任务数据不能自行扩大访问范围。代理指令、工作流和权限配置的变更应纳入相应维护者审查。
4. **共享知识经过沉淀。**会话记忆可以辅助工作；已确认的架构、业务定义与规范回写到版本控制的权威文档，避免只存在于个人设备或聊天记录。
5. **结果必须可核对。**交付记录包含工作项、变更范围、执行环境、命令与退出状态、产物位置、未执行检查和剩余限制。计划执行不等于实际通过；AI 审查意见不等于 CI 结果。
6. **保留必要证据。**不提交密钥、客户原文或完整敏感会话；用脱敏摘要及受控日志引用支持重现。

这些措施与团队的编码、测试、发布规范共同执行。根 AGENTS 只保留必要边界与入口，细节由专门规范承载。

## 6. 新项目和升级时如何验收

首次复制模板、升级代理客户端、改变工作目录结构、调整指令文件之后，执行一次小型加载验收：

| 验收场景 | 通过标准 |
| --- | --- |
| 从项目根启动 | 能指出根约定和项目验证命令的真实来源 |
| 从有局部指令的模块启动 | 能区分共享规则与模块差异 |
| 从根任务修改深层文件 | 实际读取该路径适用的局部指令 |
| Claude 的根及模块适配 | 共享内容成功加载，导入路径有效 |
| 目标 Copilot 功能 | 通过该功能的引用信息及小任务观察确认入口生效 |
| 引用文件变更 | 根导航仍到达有效权威文档 |
| 指令与代码不一致 | 报告差异并更新正确来源，不凭模板猜测命令 |
| 测试未运行或运行失败 | 交付明确标注状态，不声称完成全部验证 |

记录工具版本、功能入口、工作目录、文件组合与观察到的结果。代理自述“已遵循”只能作为辅助信息；至少搭配一次可观察的微小任务和真实检查结果。这里列的是验收方案，本研究没有启动各厂商客户端完成跨工具端到端实测。

## 7. 更新与证据维护

每月复核产品加载文档；重大版本升级、发现不加载或指令冲突时立即复核。每次更新需要说明：外部行为变化、框架采取的调整、受影响适配层、兼容验收结果、是否需要向既有项目发布迁移说明。新规则优先来自真实失败案例；连续无用、可由配置直接得出或重复的规则应删除。

本次证据均在 2026-09-20 打开核验。AGENTS 格式仓库通过 `git ls-remote` 取得提交 `d001185d792eb6402a58e4cbef1c228b309ec25d`，并打开对应文件永久链接。产品文档为滚动更新页面，不声称其 URL 是不可变快照；后续复核应以新日期记录差异，保留本研究的 Git 历史。

OpenAI 产品事实优先查找本机可用文档；本次未找到适用的本地正式参考页，继而使用 OpenAI 官方文档。未将本机其他项目或私人会话中的规则当作厂商规范，也未将某个仓库的命令直接当作通用最佳实践。
