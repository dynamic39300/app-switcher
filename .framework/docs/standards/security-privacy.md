# 安全、隐私与供应链规范

本规范适用于所有项目，具体控制随攻击面、数据和风险启用。MUST 为适用要求，SHOULD 为可调整建议，MAY 为选项。角色可以由同一人兼任；涉及真实生产风险时责任必须落到具体人，不能只填写“安全团队”。

## 1. 威胁与数据先盘点

- **MUST** 在[技术设计](../../templates/artifacts/technical-design.md)中标明资产、入口、身份、信任边界、数据去向和主要滥用方式。小型工具可使用一张表；身份、租户、资金、敏感数据或高权限 Agent 变更需要明确威胁分析。
- **MUST** 明确数据分级、使用目的、采集最小范围、访问主体、保存位置、保留期限与删除方式。日志、备份、向量索引和评估样本也属于数据资产。
- **MUST** 向模型或外部服务发送数据前，确认项目允许的数据类型、接收方、处理地域与保存/训练相关设置，并记录核验来源和日期。
- **MUST** 若项目涉及特定法律、合同或行业义务，记录适用要求与负责核验的人；本规范不能直接作为合规认证或法律结论。
- **SHOULD** 用 [OWASP ASVS](https://github.com/OWASP/ASVS) 选择和追踪具体验证要求，并在引用中固定版本及条目编号。本框架未逐条实现 ASVS，采用本文不能宣称通过 ASVS 验证。

## 2. 身份、权限与边界

- **MUST** 在可信服务端或适用可信执行层校验每个敏感动作的身份、角色、资源归属与租户边界。隐藏 UI 元素不构成授权控制。
- **MUST** 默认拒绝未明确授权的访问；测试未登录、错误角色、跨租户、过期凭据和资源 ID 替换等适用情形。
- **MUST** 服务账号、CI、Agent、数据库连接和第三方凭据按用途及环境隔离，赋予任务所需的最小权限。
- **MUST** 不可信输入使用参数化或上下文正确的编码/转义；模型输出、导入文件和工具返回值不得直接拼接为 SQL、shell、HTML 或执行代码。
- **MUST** 文件上传、URL 抓取、重定向、Webhook 和外部请求按实际攻击面限制大小、类型、目标、超时和重试，防止越界访问与资源滥用。
- **SHOULD** 复用成熟的身份与密码能力，避免自制加密、密码存储或会话协议；具体算法和参数遵循所用实现的当前官方安全建议。

## 3. 秘密全生命周期

- **MUST** 真实秘密通过批准的秘密管理方式注入，仓库只保留无秘密示例。开发和生产凭据不得互用。
- **MUST** 在提交或合入环节执行秘密检测，并记录如何处理发现。无法自动检测的环境需有明确人工替代措施。
- **MUST** 秘密不得出现在日志、错误报告、测试快照、录屏、提示上下文、复制示例或客户端包中；审阅生成资产和 CI 输出。
- **MUST** 怀疑泄露时立即撤销或轮换受影响凭据、排查使用记录并跟踪影响。删除文件或清理 Git 历史本身不恢复秘密安全。
- **SHOULD** 使用短期凭据和工作负载身份；记录 owner、权限、用途、轮换方式和离职/服务退役时的回收方式。

## 4. 依赖与构建供应链

- **MUST** 依赖、容器基础镜像和构建动作有可追溯版本；生产可执行供应链节点使用项目选定的不可变版本或摘要策略，并配置更新流程。
- **MUST** 首次引入依赖核对来源、名称、维护情况、许可证与必要性；评估安装脚本和构建插件拥有的权限。
- **MUST** 对适用依赖执行漏洞检查并分流结果，结合可利用性、暴露面和影响设定修复期限。发现高影响且可利用的问题，修复或采取已批准的补偿控制后才能发布。
- **MUST** CI 对不可信 PR 输入隔离执行，不把生产秘密交给未信任代码；仓库写入和发布权限最小化。
- **SHOULD** 生产制品记录源 commit、构建环境和依赖清单；面向外部交付或较高风险项目生成 SBOM、校验制品完整性。
- **MAY** 按客户/平台要求增加制品签名、构建来源证明和供应链等级评估；不把采用单一工具等同于达成某个安全等级。

## 5. AI 专项防护

OWASP 对[提示注入](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)的分析表明，外部内容可影响模型行为；提示文本本身不能可靠保证权限边界。以下是本框架采用的工程控制：

- **MUST** 将网页、邮件、检索片段、用户上传与工具返回视为不可信数据；其中的指令不能扩大任务授权。
- **MUST** 在工具执行层做独立的身份、动作、目标与参数校验，并限定可访问网络、文件、数据与资源预算。
- **MUST** 生产发布、删除、资金或对外通信等动作遵循项目[治理授权](../handbook/governance.md)。授权可以预先明确到限定范围；执行不得因模型建议自行扩大范围。
- **MUST** 对检索和记忆按用户/租户过滤；向量相似度不构成访问许可。缓存键和批处理不得把其他用户内容混入上下文。
- **MUST** 根据实际攻击面测试越权工具调用、间接提示注入、秘密外传和恶意输出；防护有效性以拒绝执行和数据隔离结果验证。
- **SHOULD** 保留脱敏后的动作审计和拒绝原因，支持调查；详细要求见 [AI 工程规范](ai-engineering.md)。

## 6. 响应与验收

发布前 **MUST** 有一个真实可用的漏洞/事件报告入口、受理负责人、分级与升级路径。项目尚无外部用户时可以是内部 issue 流程；公开敏感细节前先评估披露范围。

安全验收应留存：

1. **MUST** 本次改变的信任边界、权限和数据去向已审查，适用负向用例通过。
2. **MUST** 秘密与依赖检查结果可追溯，未修复问题有处置结论。
3. **MUST** 日志和遥测不会超范围收集敏感信息，访问与保存期限明确。
4. **MUST** 事故能够撤销访问、停用风险功能并追踪影响；有数据的服务按[运维规范](operations.md)验证恢复。

## 7. 适用与例外

纯本地、无敏感数据、无外部连接的原型可以不配置 WAF、正式渗透测试或企业安全平台，但仍须保护秘密并验证实际边界。SHOULD 可在项目采用记录中说明不采纳理由。MUST 的例外需要[例外记录](../../templates/artifacts/exception.md)，由有权接受风险的人确认负责人、补偿措施、影响范围和到期日；例外不得用来覆盖未满足的外部强制义务。
