# ADR-0001：使用版本化规范快照与项目差异层

本框架需要被多个独立项目复制并持续升级。我们选择将规范与模板放入项目的 `.framework/` 快照，记录版本与逐文件哈希；项目真实需求、架构与差异单独维护。这让项目能在没有网络时使用已接受的规则，也能在升级前检查变化。

考虑过直接复制所有规范到项目文档根目录，以及始终链接上游最新内容。前者让通用规则与业务材料难以区分，后者让执行规则在未评审时变化。快照的代价是增加仓库体积和显式升级工作；初始版本以清晰和可审核优先，暂不引入 Git submodule 或远程规则加载器。

项目骨架文件生成后归项目维护，上游只提供模板差异。快照升级以完整变更和 manifest 更新为单位；项目局部变化通过 overrides 和有时限例外管理。
