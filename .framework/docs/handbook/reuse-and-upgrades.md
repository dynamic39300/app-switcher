# 跨项目复用与持续演进

## 复用什么

| 资产 | 复用方式 | 兼容要求 |
| --- | --- | --- |
| 通用规范和材料模板 | `.framework/` 固定版本快照 | 记录版本与源文件哈希 |
| 设计 tokens、组件 | 有版本的包或明确所有者的源码模块 | 视觉/无障碍基线、变更说明 |
| API、事件和 Schema | 机器可读契约 + 消费者测试 | 字段、错误、权限、事件语义兼容 |
| 业务能力 | 独立包/服务，按边界与成本选择 | owner、许可、支持期与弃用计划 |
| Agent 技能/提示/eval | 最小输入输出与版本化资源 | 权限、工具版本、评测与数据许可 |

先验证两个实际使用场景，再考虑提炼共享能力；这是 SHOULD，明确已有稳定领域边界时可提前建立。不能为了复用把项目间全部数据模型和发布周期耦合在一起。每个共享资产记录消费者、负责人、版本与迁移支持，统一入口见[共享资产目录](../catalog/README.md)。

## 升级设计

规范由本仓库维护。生成器把选定文件原样复制进业务项目 `.framework/`，在 `.framework/manifest.json` 写版本、生成时间和 SHA-256。业务项目的根 Agent、`PROJECT.md`、`docs/` 和 CI 属于项目本身，模板上游更新只提示差异，不自动覆盖这些文件。

快照内不要直接写项目定制，定制放在 `docs/project/overrides.md`。必须修正快照时保留 diff 并尽快上收；哈希检查会提示漂移。

哈希基于原始文件字节，根目录和项目骨架使用 `.gitattributes` 固定文本 checkout 为 LF，避免 Git 跨平台换行转换造成误报；`.editorconfig` 约束编辑器写入。项目保留这一规则，二进制文件由 Git 自动判定。

从新框架目录比较已采用项目：

```sh
python3 scripts/compare_framework.py --project ../my-product
python3 scripts/compare_framework.py --project ../my-product --json
```

报告分别显示上游快照变化、本地快照漂移和项目骨架模板变化。工具只读；发现差异不代表错误，也不执行自动合并。丢失/非法 manifest 会失败。

## 可评审升级步骤

1. 项目 owner 读取目标版 CHANGELOG，确定影响、优先级和回退方式；规范修订不自动生效到所有项目。
2. 在独立工作分支保留当前项目，运行差异报告；本地漂移逐项决定上收、迁入 overrides 或保留说明。
3. 用目标版本生成一个临时项目；比较它的 `.framework/` 与当前快照。检查 manifest 和版本一致后，将新快照作为一次完整变更引入。
4. 按差异报告人工合并根 Agent、CI 和项目文档模板变化，保留原业务内容；不会由复制过程自动完成。
5. 执行文档检查、实际业务测试和 Agent 入口验收；检查因新规则产生的缺口，登记有期限的例外。
6. 更新 `PROJECT.md` 采用版本和升级记录，由适当 owner 评审；失败则回退整个升级提交及相关项目配置。

`0.x` 期间可能有破坏性调整，所有版本都检查迁移说明。进入稳定版后使用 MAJOR 表示不兼容规则/结构变化，MINOR 表示兼容扩展，PATCH 表示修正；版本号表达兼容意图，不能代替实际 diff。

## 持续研究与反馈

| 周期/触发 | 动作 | 产物 |
| --- | --- | --- |
| 每月，或 Agent/SDD 工具大改 | 复查上游仓库、加载规则与兼容性 | 来源核验、采纳/延后/拒绝及理由 |
| 每次项目里程碑/事故后 | 提炼返工、缺陷与规则成本 | 复盘、候选改进 ticket |
| 每季度 | 合并重复规则、移除无效门槛、评估项目指标 | 基线提案、试点范围、版本计划 |
| 紧急安全/兼容问题 | 缩短周期，明确影响版本与临时措施 | 补丁、迁移说明、消费者通知责任 |

来源登记至少包含：原始 URL、核验日期、commit/版本、观察、采纳边界、owner、下次复查。优先官方仓库和官方文档，不用 stars 排名代替适用性判断。工具变化先在临时项目验证，不直接执行远端未知安装脚本。

候选规则流程：`观察 → 提案 → 一个真实项目试点 → 结果评估 → 接受/修改/拒绝 → 发布 → 消费项目选择升级`。评估采用成本、返工变化、缺陷和交付结果；数据不足标为试验性 SHOULD/MAY，避免立即升级为所有项目 MUST。

本仓库的日期检查只在运行时提醒；尚未创建定时任务或自动通知。组织可将复查纳入自己的日历/任务系统，另行配置定期执行与责任人。
