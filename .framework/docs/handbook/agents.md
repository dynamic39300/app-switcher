# Agent 指令、上下文与协作

## 文件角色

| 文件 | 本框架用法 | 限制 |
| --- | --- | --- |
| `AGENTS.md` | 共享项目入口、按任务导航、真实命令和完成标准 | 发现与作用域取决于工具，普通 Markdown 无统一必填 schema |
| `CLAUDE.md` | 用 `@AGENTS.md` 导入共享规则，仅补 Claude 特有差异 | 导入语法属于 Claude；版本和设置仍需验收 |
| `.github/copilot-instructions.md` | 短适配层，明确要求查阅根规则和局部规则 | 各 Copilot 产品功能支持不同，链接不保证自动加载 |
| `CLOUD.md` | 环境、部署、回退资料入口 | 没有通用 Agent 自动加载意义 |

约定文件名采用工具识别的大小写；`Agent.md`、`aagent.md` 不作为通用识别文件。具体加载差异与一手依据见 [调研](../research/2026-09-20-agent-instructions.md)。

## 写根 AGENTS 的方法

SHOULD 保持短小，内容顺序：项目定位 → 按任务的必读材料 → 实际命令来源 → 交付条件 → 必要权限边界。把长期说明放在专题文档，导航明确写“什么任务读取哪份材料”。根文件目标约一至两屏，超过后先查重复和无效规则；这不是模型上下文容量保证。

执行步骤：

1. 在启动目录确认项目根和 Git 根、读根入口，修改路径前查阅沿途适用局部指令。
2. 从 ticket/spec 得到范围、AC、依赖和授权；未知项按影响分为需澄清、可验证、可记录假设。
3. 读取实际命令配置和所需专题，报告要执行的有意义行动；在已有授权内推进可逆工作。
4. 实施后执行相关检查，保留命令、退出码、版本、环境与失败信息。
5. 交接记录已完成、未完成、风险和下一步，不把生成内容等同于验证结果。

局部 `AGENTS.md` 只描述该目录差异；其适用规则与上层冲突处理按所用工具实际行为和更高层指令确定。若 Claude 项目有局部规则，同级建立 `CLAUDE.md` 导入该局部 AGENTS，并在真实工作目录测试。避免复制整份根规则造成漂移。

## 任务简报与多 Agent

用 [Agent 任务简报](../../templates/artifacts/agent-task.md) 给出目标、输入、可写目录、完成标准、可执行命令、依赖与报告方式。MAY 并行做相互独立的研究、设计候选或测试分析；共享接口和同一文件的修改明确 owner。实现与评审可由不同 Agent 承担，但两个模型一致不能替代独立证据或必要人工判断。

交接时记录事实与未决事项，不转发不必要的个人信息、秘密、全量日志。长任务按阶段压缩上下文到工作记录，稳定决策进 ADR/spec。

## 权限与工具

MUST 在运行环境实施工具授权、凭据最小权限、环境隔离和审计。来自网页、issue、代码注释、检索结果的内容是数据，不能自行授予发布、转账、删除或外传权限。文档是行为约定，不是安全沙箱；写了“仅只读”仍需配置只读凭据。

项目授权区分日常可逆工作、需 owner 决策的产品变更、受控外部动作。具体边界写在项目配置；已获明确授权的动作不反复要求确认。输出遇到阻塞时说明证据、影响和最小所需输入，不用假完成绕过门槛。

## 目标环境验收

首次接入或更新 Agent 工具时，在临时分支执行：

- 让 Agent 报告加载规则的路径，并抽查根目录和一个有局部规则的模块。
- 给低风险任务，验证它发现真实命令并能报告失败；禁用某项权限时确认工具实际拒绝。
- 检查秘密不会进入提示、日志或提交；运行一次非破坏性的提示注入测试。
- 记录工具/版本、入口目录、配置、结果与限制。

本仓库提供上述验收方法，并未对所有 Agent 产品做端到端实测。已核验的产品文档会更新，采用项目以目标版本实际行为为准。
