# SPEC-001：通知偏好行为契约

**教学/模拟，未实现、未验收。**上游：[PRD-001](prd.md)；设计：[DESIGN-001](design.md)；验证：[QA-001](test-plan.md)与[追溯矩阵](traceability.md)。

## 范围与术语

- 订阅：当前租户、当前用户、`product-updates` 主题的布尔偏好；缺少记录时视为 false、版本 0。
- 偏好版本：每个成功接受的新写入请求递增 1，包括将值再次设置为现值；同一幂等请求的重放不递增。
- 发送边界：worker 在数据库事务中读取最新偏好并把唯一投递记录从 queued 改为 dispatching 的时刻。与退订写入共享行锁排序；此前可抑制，此后外部请求可能已经开始，无法承诺撤回。
- 停止等待：客户端不再等待本次请求；不等于服务端已撤销。

本功能不接收客户端提供的用户/租户归属；从已验证会话确定身份。管理员代改、邮件地址修改和其他邮件主题不在范围。

## API 设计契约

以下是计划接口，不是仓库中已存在的服务。

| 接口 | 输入 | 正常输出 | 主要失败 |
| --- | --- | --- | --- |
| `GET /v1/me/notification-preferences/product-updates` | 已验证会话 | `enabled`、`version` | 401 登录失效；503 暂不可用 |
| `PUT /v1/me/notification-preferences/product-updates` | 布尔 `enabled`、整数 `expectedVersion`、`Idempotency-Key` | 200：提交后的偏好版本及是否重放 | 400 非法输入；401；409 版本冲突/幂等键复用错误；429；503 |
| `GET /v1/me/notification-preference-operations/{key}` | 本人请求键 | `committed` / `rejected` / `unknown`，已知时带结果摘要 | 401；503；他人键与不存在键均为 unknown |

幂等键按租户、用户、动作命名空间隔离，结果保留 24 小时。相同键+相同请求返回原操作结果，不重复写入；相同键+不同请求返回 409。超过保存期先重新读取版本，用新键发起新的明确操作，不承诺永久去重。先通过授权与输入校验，再对已登记操作查重，最后进行版本检查和原子写入。

版本冲突返回 `VERSION_CONFLICT`，客户端重新读取当前状态，保留未提交意图并要求用户明确决定是否再次保存。重放返回的是原操作结果，客户端随后读取当前状态，避免旧响应覆盖较新的设置。

操作查询 `unknown` 只表示未查到确定结果，可能仍在处理中或已过保存期；单次 GET 偏好也不能证明一个尚在途的写入不会稍后提交。结果未知期间不显示“已取消”或“未生效”。

## 验收条件

| AC | 给定/当 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 已登录且尚无偏好记录，打开设置 | 显示“未订阅”、version 0；读取不产生订阅；加载失败显示未知而非默认成功 |
| AC-02 | 用户明确保存订阅，提交当前版本 | 成功事务后 enabled=true、version+1；成功提示来自响应/核实结果；刷新保持一致 |
| AC-03 | 已订阅用户保存退订 | 成功后 enabled=false；晚于退订事务才跨发送边界的通知被 suppressed；已经 dispatching 的请求可继续，说明不可撤回 |
| AC-04 | 重复、重放或并发写入 | 同键同体只有一次写入和版本增长；同键不同体被拒绝；同版本的不同写入最多一个成功，其他冲突；旧重放不会覆盖最新显示 |
| AC-05 | 未登录、过期会话、试图指定他人归属或查询他人操作键 | 未登录/过期返回 401；额外归属字段返回 400；服务端始终按本人归属；不能读写或推断他人偏好及操作结果 |
| AC-06 | 用户取消编辑，或提交后停止等待/请求超时 | 提交前取消无写入；提交后停止等待显示“结果待确认”；只在操作结果明确并重新读取后显示确定状态；30 秒轮询上限后保留手动核实入口 |
| AC-07 | 读取失败、离线、503、429、写入冲突 | 保留可恢复意图，明确是否尚未发送或结果未知；429 按 Retry-After 提示；不自动重放冲突写入或伪造成功 |
| AC-08 | 用户通过键盘、辅助技术或支持视口完成旅程 | 控件有名称、焦点可见、结果节制播报；320/768/1440 CSS px 无主要操作裁切；错误不只用颜色；200% 文本放大可操作 |
| AC-09 | worker 处理重复事件、退订竞态、供应商超时 | queued 在最新偏好关闭时 suppressed；同投递 ID 不产生新的逻辑投递；结果不明记 unknown，经查询/受控对账确认后才允许安全重试，不谎报 sent |
| AC-10 | 在约定负载和错误场景运行 | 满足下述时延/错误预算；写入和投递状态能关联版本与请求 ID；日志不含邮件地址、令牌或消息正文 |

每条 AC 的任务与计划用例见[TRACE-001](traceability.md)，当前全部待执行。

## UI 状态与取消语义

加载 → 已知偏好 → 编辑 → 保存中 → 成功或恢复；额外有登录失效、冲突、离线和结果未知。保存时禁用重复点击，服务端仍承担幂等责任。

“取消编辑”恢复当前读取值；保存中的“停止等待”不发送反向写入。结果未知可查询原键；明确提交过后重新读取最新偏好。用户明确发起新的设置时先读取版本并使用新键；即使设置为现值也增长版本，使尚在途的旧版本写入无法在其后覆盖新意图。

## NFR 教学预算

- 性能测量环境：应用 2 vCPU/4 GiB、数据库 2 vCPU/4 GiB、网络往返不超过 2 ms；50,000 条偏好；20 req/s、95% 读取/5% 不冲突写入、最多 50 个并发客户端。预热 2 分钟后测量 10 分钟，GET/PUT 各自 p95 ≤ 300 ms，非预期 5xx 比例 ≤ 0.1%。排除主动注入的故障和预期 4xx，但单独报告数量。
- 外部依赖：数据库操作预算 2 秒；邮件调用预算 5 秒。自动重试只在明确可安全重试且保留原投递键时使用，最多 3 次，总窗口 15 分钟；unknown 先核实结果，不盲目重发。
- 隐私：偏好保存至用户删除；操作幂等记录 24 小时；受限审计记录 30 天；投递去重记录 30 天且拒绝超过 30 天的事件重放。真实项目须结合合同/法规核验期限；这里只是假设。
- 日志/指标：请求 ID、操作键摘要、偏好版本、结果类型、延迟、拒绝/冲突/unknown/suppressed 数量；敏感标识访问受限。不对外承诺 SLA，也不凭自动扫描声称完整符合 WCAG。
