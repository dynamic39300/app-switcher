# REL-001：通知偏好候选发布计划

**教学/模拟，尚未构建、未部署、未发送邮件。**关联：[TASKS-001](tasks.md)、[QA-001](test-plan.md)、[TRACE-001](traceability.md)；规则：[运行规范](../../docs/standards/operations.md)。

## 范围与版本

范围：SPEC-001/AC-01 至 AC-10。源 commit、构建制品摘要、运行配置、迁移版本、供应商适配版本：全部待产生。真实环境、操作者、授权记录和发布日期：全部待指定。

本计划不是部署授权。真实业务项目须先核验邮件渠道要求、权限体系和供应商行为，再在已授权范围内执行。

## 从 planned 到 ready 的条件

- PRD/Spec/设计由真实 owner 形成一致基线，TKT-001 至 TKT-005 有版本、验收和必要独立审阅。
- QA-001 的适用用例通过，失败已修复或按治理形成有效限时例外；权限泄露、违规发送、结果虚报不能以忽略测试来通过。
- 在候选制品上验证迁移、恢复与关键旅程；供应商幂等/结果查询已核验，测试替身结果不能代替真实接入验证。
- 实际发布命令、环境隔离、秘密来源、操作授权、观察与停止责任明确。

上述条件当前均没有执行证据，因此维持 planned。

## 计划顺序与观察

1. 准备备份/恢复证据；以兼容方式新增表与索引，默认 false，不回填为订阅。
2. 发布 API 和 UI，发送开关默认关闭；用授权测试主体确认读取、保存、退订及 unknown 恢复。
3. 小范围开启发送门禁，观察至少 60 分钟；扩量条件为无权限/发送边界错误、错误预算与队列延迟可接受，值守人实际确认。
4. 继续观察 24 小时并汇总关键旅程、API 5xx/延迟、unknown 数与年龄、suppressed 和队列积压。教学阈值须在真实基线下校准，不能直接当作生产 SLA。

立即停止发送并升级：发现跨用户访问或退订边界后仍启动发送。其他停止条件：非预期 5xx 连续 5 分钟超过 1%，或存在超过 15 分钟未核实的 unknown 投递；首先保留证据并核实影响，不能盲目重放。

## 回滚、恢复与未撤回副作用

在项目事故授权内暂停 worker/关闭发送开关，保留退订、幂等、去重与审计数据。必要时回滚代码到已验证的兼容制品；不删除新表、不把偏好重置为 true、不恢复旧发送通道绕过门禁。旧版本不支持该边界时保持发送暂停并前滚修复。

核实 unknown 投递的供应商状态后才决定安全重试；已发送邮件无法撤回。恢复后检查最新偏好、 queued/suppressed 状态、权限和关键用户旅程，证明退订没有因代码回滚而丢失。
