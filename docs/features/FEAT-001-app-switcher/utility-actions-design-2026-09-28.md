# UX-001：桌面、设置与退出应用的交互设计提案

日期：2026-09-28。Owner 已确认退出只通过应用卡片的鼠标叉触发，并授权开始开发。本文是交互基线；本轮实现与验证见 [TKT-019](tasks.md#tkt-019公共入口与应用退出2026-09-28)。当前安装中的 0.5.0 不受工作区代码影响。桌面入口仍受下述公开 API 技术门槛约束，不把未实现状态写成已交付。

## 1. 目标与设计原则

目标用户在唤出键盘面板后，不离开当前切换流程，就能到桌面、打开本产品设置，或正常退出某个正在运行的应用。这里的“退出”是**退出选中的应用进程及其所有窗口**，不是关闭一个窗口、隐藏、最小化或强制结束进程。

- 公共动作与切换目标分层：桌面、设置属于面板工具，不占 38 个应用/窗口键位，也不参与排序、拖拽改键或使用统计。
- 对目标的高影响动作与主操作分层：键帽主体点击、字母键和 Enter 只做“切换”；应用卡片右上角的独立叉是唯一的退出入口。目标应用自己的未保存内容提示保持原样。
- 尽可能沿用 macOS 语义：桌面遵循系统“显示桌面”行为，退出使用正常退出请求；不把打开 Finder、批量最小化或强制退出作为隐式替代。
- 面板尺寸和模式不因加入公共动作而变化；工具栏、键盘、底部反馈仍保持清楚的视觉层级。

## 2. 信息架构与布局

```text
┌ AppSwitcher · 切换应用/窗口 ───── [主题] [应用 | 窗口]  [桌面] [设置] [×] ┐
│                             38 键候选区                                  │
│ [S                 ×] Spotify               切换：S / Enter                │
│ Tab 切模式 · 方向键选择 · Enter 切换 · Esc 关闭                            │
└───────────────────────────────────────────────────────────────────────────┘
```

应用卡片左上角固定显示键位，右上角在鼠标悬停或辅助技术聚焦该控件时显示独立的叉。卡片主体点击仍切换；叉的命中区只请求退出，不触发切换或拖拽改键。不增加键盘组合、退出状态或右键菜单中的重复退出入口。在窗口模式不展示叉；需要退出整个应用时先返回应用模式。

当前工具栏高 42 pt，右侧已有主题、模式、齿轮、关闭。常规宽度下“桌面”“设置”均用图标加文字，视觉样式与模式按钮同一层级；工具栏“×”只表示关闭切换器，与卡片内“退出整个应用”的叉通过位置、尺寸和完整提示区分。紧凑宽度下先把三种主题折叠成菜单，再让“桌面”“设置”保留 32–36 pt 图标按钮及完整 tooltip/无障碍名称；极窄屏不得让公共入口或关闭键被裁切。桌面图标不使用 Finder 图标，以免暗示仅激活 Finder。卡片叉默认安静、悬停/聚焦时才明显呈现；警示色不覆盖整张普通键帽。

工具栏顺序按“外观 → 模式 → 桌面 → 设置 → 关闭”。键盘焦点顺序与可见顺序一致；原有 Tab 仍切换应用/窗口模式，不被工具栏接管。可使用系统键盘导航或 VoiceOver 访问按钮；每个图标按钮有可读名称和操作提示。悬停、焦点、按下、禁用状态需要沿用三主题语义色；高对比度和减少动效设置沿用现有规则。

## 3. 桌面入口

### 3.1 用户语义

按钮可见名称建议“桌面”，完整提示为“显示或返回桌面”。第一次从普通应用/窗口状态触发时，收起 AppSwitcher 并呈现当前 macOS 显示器/空间的桌面；系统支持的再次触发可让窗口回到原位。它是系统级往返动作，**不是**一个会保留在 38 键列表中的“桌面应用”，也不保证所有桌面图标在用户系统设置下可见。

面板应先结束本轮候选快照和按键监听，再触发桌面动作；不能先恢复之前的前台应用、又把面板留在窗口之上。桌面动作不改变第三方窗口的最小化、隐藏或关闭状态，不写入键位配置。用户随后按原唤出键仍能打开 AppSwitcher，选择 App/窗口继续工作。

**实现门槛**：Apple 文档明确有“显示桌面”系统动作，且其键盘快捷键可由用户更改；当前尚未验证本产品能否使用公开、稳定的方法触发它。因此开发前要做隔离技术 spike。不得硬编码某一组系统快捷键后声称对所有用户有效，也不得以激活 Finder、隐藏全部 App、逐个最小化窗口来冒充原生行为。如果无法达到这一语义，应先回到产品评审，决定是否明确改名为其他动作。依据：[Apple 调度中心说明](https://support.apple.com/en-bh/guide/mac-help/mh35798/mac)、[Apple 键盘快捷键](https://support.apple.com/zh-cn/102650)。

### 3.2 状态与反馈

| 情况 | 预期体验 |
| --- | --- |
| 应用模式、窗口模式、候选为空 | “桌面”始终可见；不依赖候选数量或 AX 窗口权限。 |
| 窗口正在异步扫描 | 点击后取消扫描、收起面板；迟到结果不能重开面板或改写下一轮快照。 |
| 快速连击 / 按键自动重复 | 一轮操作只触发一次系统动作，不因双击无意恢复窗口。 |
| 系统已在显示桌面 | 再触发遵循“显示或返回桌面”的系统往返语义；具体状态识别和跨显示器行为需 spike 证实，不伪装成永远单向。 |
| 系统动作无法触发或结果无法核对 | 不显示“已回到桌面”；若面板仍能安全恢复则在面板内说明，否则下次唤出显示“未能确认桌面切换，请使用 macOS 的显示桌面快捷键”。 |
| 多显示器、全屏、不同 Space、台前调度 | 逐项实测并记录实际系统行为；不承诺主动移动窗口或强行切换 Space。 |

首版不增加单独的全局“桌面”热键；现有全局唤出键加一次面板点击已满足公共入口，避免与 macOS 可配置的系统快捷键竞争。

## 4. 设置入口

现有右上角齿轮及菜单栏“快捷键设置…”已进入同一个原生设置窗口；此处优化其可发现性和键盘可达性。工具栏改为图标加“设置”，面板有焦点时 `⌘,` 打开同一设置窗口。菜单栏入口继续可用，尤其当候选为空、唤出键冲突或商业授权状态导致切换面板不可用时，用户仍可进入设置。

从面板打开设置时，先结束本轮面板会话，再将已存在的设置窗口带到前台；不复制窗口，不让面板内的 38 键选择与快捷键录制争用。关闭设置后不自动重新唤出面板，返回系统自然焦点。录制、草稿、保存和取消规则仍按 [SPEC-001](spec.md#唤出快捷键设置) 执行。

**范围建议**：这一轮只统一设置入口和名称，设置窗口仍以现有快捷键配置为首屏。外观、账号与授权、权限、更新未来可以汇入设置中心，但不应为了增加公共入口同时重做所有设置页。若按钮名称写“设置”，窗口标题应明确“设置 · 快捷键”，避免用户以为其他设置已经搬入。商业账号等原有入口继续保留。

| 情况 | 预期体验 |
| --- | --- |
| 设置已打开 | 复用并前置同一窗口，草稿不被覆盖。 |
| 正在拖拽改键、主题切换或窗口加载 | 完成/取消当前局部手势后才导航；不发生改键与导航的双重提交。 |
| 设置窗口录制中再次尝试唤出面板 | 保持现有录制暂停和会话规则，不把录入的组合误触发为切换键。 |
| 无障碍权限或网络不可用 | 本地快捷键设置仍可进入；各设置项各自显示真实可用状态。 |

## 5. 退出选中应用

### 5.1 触发、对象和目标应用原生提示

首版只在**应用模式**提供退出。每张应用卡片**右上角独立的叉**是唯一产品入口：鼠标移到卡片后显现，悬停提示为“退出「Spotify」应用（关闭所有窗口）”。点击叉直接请求该应用正常退出，不叠加 AppSwitcher 的通用确认框；卡片主体、对应字母键和 Enter 仍只切换，图标拖动仍改键。叉只绑定被点击卡片的精确运行实例；同一实体应用的不同进程如果各占一个候选，也不按显示名称、窗口标题或 bundle ID 猜测另一个实例。

当前键位字母位于卡片右上角，与新叉冲突。提案将键位字母固定移到**左上角**，叉占**右上角**，均不得覆盖图标或名称；常规卡片的叉有独立至少约 28–32 pt 命中区，视觉符号可更小。短屏、38 键和窄卡片须用原生尺寸预览检验：必要时调整边距或符号位置，不能靠把已放大的应用图标显著缩小来塞入叉。叉的点击不能冒泡为卡片切换，也不能被现有拖拽手势吞掉；仅悬停不执行任何动作。为了让鼠标以外的辅助技术用户使用同一个控件，叉保留系统标准的键盘聚焦/VoiceOver 激活能力，但不提供额外的产品快捷键或第二条退出路径。

不为退出注册或拦截任何组合键；现有自定义唤出键、`⌘Q` 退出 AppSwitcher，以及 38 个切换键的行为保持原样。窗口模式不在具体窗口卡片上放叉，避免把“退出整个应用”误认为“关闭此窗口”。

提交退出请求前先收起切换器，并让被选中的运行实例获得前台处理机会；若目标弹出保存提示，该提示必须能被用户看到和操作，不能留在 AppSwitcher 面板后面。只激活这个精确进程，不通过 reopen 创建窗口或切换到同名的其他进程。**AppSwitcher 不探测文档是否已编辑，也不代替目标应用弹出“保存/不保存/取消”对话框。** 若目标应用有未保存内容，它可以按自己的规则询问保存、放弃或取消；用户选择取消时应用继续运行，用户选择保存或放弃并完成退出时才算退出成功。部分应用会自动保存，或自行决定不提示，AppSwitcher 不能保证每个有编辑内容的应用都会弹窗。没有提示且目标实际结束时直接完成，不额外打断用户。[Apple 对应用延迟或取消退出的说明](https://developer.apple.com/documentation/appkit/nsapplication/terminatereply/terminatelater?changes=_3&language=objc)。

只发一次正常退出请求，不自动转为强制退出，不在此流程中提供“强制退出”。Apple 的 `NSRunningApplication.terminate()` 只表明退出请求是否送出，可能在实际退出前返回；需要进一步观察目标是否结束。[Apple API 文档](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate%28%29?changes=_4_1&language=objc)。若未来改走 App Sandbox，Apple 明确说该 API 不能退出其他应用，届时须重新评估产品能力，不能沿用此承诺。

### 5.2 请求、等待和结果

| 状态 | 给用户的反馈与动作 |
| --- | --- |
| 候选为空、正在加载、正在激活或正在拖拽 | 退出叉禁用或不显示，不提交退出请求。 |
| 候选已消失 / PID 被新进程复用 / 身份不符 | 不退出任何替代实例；留在面板并提示“应用已变化，请重新选择”。 |
| 仅悬停叉、按普通键位或点击卡片主体 | 不发送退出请求；候选仍可正常切换或拖拽。 |
| 请求成功送出但尚在运行 | 面板收起，目标应用获得处理保存提示的机会；轻量状态提示“已请求退出「Spotify」；如出现保存提示，请在应用中处理”，不显示“已退出”。 |
| 目标实际结束 | 轻量状态提示更新为“已退出「Spotify」”；候选在下一轮重新枚举，键位按既有规则重算。 |
| 用户在目标应用原生提示中选择“取消”，或应用拒绝退出 | 应用继续运行；AppSwitcher 不重发请求、不强制结束。只有观察到进程仍在运行，不猜测用户具体选择。 |
| 目标短暂等待后仍在运行 | 轻量状态提示更新为“「Spotify」尚未退出。请切换到该应用，检查保存或退出提示。”并提供“查看应用”操作。 |
| 请求无法送出 | 返回面板并说明“未能请求退出「Spotify」，请切换到该应用手动退出”；保留原选择供用户重试。 |

正常退出之后如果应用自己显示保存确认，AppSwitcher 不替用户选择“保存/不保存”；用户作出选择后才能最终判断是否退出。验证目标退出可依据同一运行实例的终止状态与工作区通知，不能仅凭 `terminate()` 返回 `true`。Apple 的工作区终止通知对普通 App 可用，但文档指出后台及 `LSUIElement` App 不发送该通知，因此仍需要对象状态核对。[Apple 通知文档](https://developer.apple.com/documentation/appkit/nsworkspace/didterminateapplicationnotification?changes=l_2_2)。

反馈不能只藏在“下次唤出”里。面板收起后，状态由一个**不抢焦点、不遮挡中央系统对话框的轻量提示**承载；它在原面板所在显示器边缘展示请求中、已退出或尚未退出，短时自动收起。点击“查看应用”才主动切换到那一个应用进程。提示消失后最近一次未完成结果仍可在下一次唤出时看到一次，但不持续弹窗催促。状态检查应给目标应用处理原生保存对话框的时间；超时只能断言“尚未退出”，不能推断“退出失败”或“用户已取消”。提示的具体位置、时长、跨 Space/全屏可见性需在原型和真实 Mac 中验证；若无法保证不挡住目标保存提示，要改用同等及时、可见且不抢焦点的呈现方式，而不能只留一条下次唤出的消息。

首版禁用 AppSwitcher 自身、Finder/系统关键进程的目标退出；其他普通应用按真实进程能力决定。针对无法安全区分目标进程的情况保守拒绝。退出不记作“切换使用次数”，不持久化窗口标题、文档名称、退出原因或未保存内容。

## 6. 共用状态、可访问性与评审门槛

- 桌面和设置在应用模式、窗口模式、空态和窗口加载态均保持可达；退出只在应用模式且目标稳定时可达。所有动作在本轮会话只提交一次。
- 一次卡片叉点击只提交一个退出请求；请求在途不重复提交，目标应用的保存对话框由目标自己管理。Esc 仍按原语义关闭面板。
- VoiceOver 读出“桌面，显示或返回桌面”“设置，打开快捷键设置”“退出 Spotify，退出整个应用”；卡片叉和失败消息可被读屏发现，危险动作的对象和影响范围不只靠颜色区分。
- 三套主题、最窄/常规/超宽屏、38 键与数字行、中文和英文长应用名、200% 放大、高对比度、减少动效，都要检查公共入口不被遮挡或误点。当前完整无障碍和放大验证未完成，不作已符合声明。
- 不因这些入口扩大对第三方窗口标题、屏幕内容或按键流的采集。桌面与退出结果只保留最小会话状态；无需网络请求。

进入实现前需要 owner 对齐的结论：① 桌面采用系统“显示/返回桌面”往返语义；② 设置本轮只统一入口，暂不重做设置中心；③ 退出仅针对应用模式的整个应用，鼠标点目标卡片右上叉为唯一显式入口，不新增退出快捷键、退出状态或右键退出项，不叠加通用确认框；目标应用自己决定是否出现保存/取消提示，首版没有强制退出；④ 请求发出后有及时可见的“请求中/已退出/尚未退出”反馈。技术 spike 若不能满足桌面原生语义、独立叉命中或反馈不挡原生提示，回到设计评审，不以近似行为悄悄替换。

开发核对：设置与应用卡片叉已进入工作区实现；桌面动作经 Apple 系统说明、Developer 文档和本机 SDK 核对，未找到公开、稳定、可直接调用的 Mission Control“显示桌面”动作。`CopySymbolicHotKeys` 可读系统快捷键列表，但系统“显示桌面”的 ID 映射未在公开 SDK 中定义；固定发送 F11/⌘Mission Control 在用户改键后不可靠。该入口暂不放入可运行面板，后续需选择经验证的公开触发方案或由 owner 明确调整语义。

验收目标：用户能在空态及 38 键拥挤态找到桌面/设置；一次点击桌面后面板不遮挡系统桌面且第三方窗口状态未变；`⌘,` 与齿轮打开同一设置窗口；应用模式 Spotify 卡片叉只请求同一 Spotify 进程退出，`S` 与卡片主体仍只切换，图标仍可拖拽改键；无新的退出组合键，`⌘Q` 仍退出 AppSwitcher；目标无需确认时可直接退出，需要确认时其原生保存/放弃/取消提示可见可操作，取消后目标仍运行；请求被拒、等待中和已终止分别有准确即时反馈，在窗口模式和目标失效时不误退任何进程。
