# 商业化：试用、离线与售后规则调研及建议

核验日期：2026-09-25。本文仅为产品规则草案；未实现账号、授权、支付或售后功能，不修改当前本地版的使用规则。行业事实均来自产品方官方页面；具体参数建议不代表行业统一标准。

## 已确定的前提

- 首发服务中国大陆个人用户，以大陆公司或个体工商户经营；macOS 先行，Windows 后续；海外支付和市场暂缓，但保留扩展边界。
- 一个账号不限制设备数量或类型；不增加并发登录、在线设备配额等隐性限制。产品支持的平台与系统版本仍应在下载页说明，不把“设备类型不限”写成尚未交付 Windows 等版本的承诺。
- 月、季、年主动购买，自动扣款后置；登录、试用权益、付费权益、支付订单分别处理。
- 用户同意完整试用和短期离线可用的方向；下面的期限、提醒、退款参数仍是本项目建议。

## 官方规则提供的参照

| 产品 | 已核验事实 | 对本产品的启发与边界 |
| --- | --- | --- |
| BBEdit | 提供 30 天全功能评估；之后进入可长期使用的免费模式，购买许可证可恢复专属功能；免费模式用户升级到 BBEdit 16 可获得新一轮评估。[官方产品页](https://www.barebones.com/products/bbedit/) | “限时全功能 → 免费基础版”是一种选择。不能由此推导所有软件都应永久保留核心功能，也不能照搬其大版本重新试用规则。 |
| BetterTouchTool | 官方安装文档明确 45 天无功能限制试用，之后需购买；购买邮件提供激活链接/许可证文件，遗失时有找回和联系支持路径。[官方安装与许可说明](https://docs.folivora.ai/docs/getting-started/installation/) | 同属高频 Mac 效率工具，证明较长试用存在；但本次页面没有说明 45 天是否扣除未使用日，不能写成“45 个实际使用日”。许可证找回应转化为 AppSwitcher 的账号权益恢复。 |
| 1Password | 14 天免费试用；订阅失效后仍可查看、复制与导出已有数据，但不能新增、编辑或浏览器填充；网页登录 Billing → Subscribe 可恢复功能。[计费说明](https://support.1password.com/membership-billing-policy/)、[到期冻结与恢复](https://support.1password.com/frozen-account/) | 到期可以限制核心服务，同时保留数据与恢复入口。该产品的自动订阅、家庭成员规则并不是我们首期的购买模型。 |
| CleanShot X | 自营购买路径不提供免费试用，而是 30 天退款保障；付款后邮件有收据和许可证；License Manager 提供找回入口，FAQ 也提供账单和重新下载路径。[官方 FAQ](https://cleanshot.com/faq) | 先付费后退款与先免费试用是两种不同路径；不能称为“30 天免费试用”。统一账户中心比把售后入口散在邮件里更适合我们的账号模式。 |

补充离线参照：JetBrains 官方说明，用账号联网激活后可离线使用最多 30 天，然后需联网验证许可。[官方离线许可 FAQ](https://sales.jetbrains.com/hc/en-gb/articles/206544169-Do-I-need-and-internet-connection-to-activate-and-use-JetBrains-products)。这证明“本地运行 + 定期联网验证”是现成模式，并不证明本产品也应使用 30 天，或可以在付费到期后额外使用 30 天。

这些例子说明行业存在 14、30、45 天以及不提供免费试用等不同选择。未发现统一周期；本次也没有证据证明哪种期限能给 AppSwitcher 带来最高转化率。

## 建议的首期试用规则

建议先采用 **14 天完整功能、无需绑定支付方式、每账号一次**。AppSwitcher 的核心价值可在日常切换中持续体验，两周包含多个工作日和周末；选择 14 天是待验证的产品假设，不是沿用竞品就能保证转化的结论。

| 项目 | 建议规则 |
| --- | --- |
| 开始计时 | 用户完成网页登录，在 App 明确点击“开始 14 天试用”，服务端成功发放权益时起算。仅下载、注册或登录官网不消耗试用。 |
| 时间单位 | 连续 14 × 24 小时，以服务端时间为准；页面展示准确到期日期、时间与时区。未打开 App 的日子仍计时，不暂停。 |
| 能力 | 与同版本付费账号相同的核心功能，不设切换次数限制，不在试用中添加水印或干扰切换。 |
| 多设备 | 所有设备共享同一个试用开始与结束时间；新增设备不扣名额、不延长试用、不重置试用。 |
| 再次领取 | 重装、更新、退出再登录、换电脑都不重新领取。同一账号第二次领取返回原试用状态。首期不为了阻止多邮箱注册而收集硬件指纹或加设备上限。 |
| 试用中购买 | 不丢失已承诺的剩余试用时间；付费期从尚未结束的试用之后承接，具体周期计算与续费文档保持一致。 |
| 提醒 | 第一次开启展示准确日期；剩余 3 天、1 天在设置/账号页与低干扰入口提醒。一次唤出不反复弹促销；邮件提醒单独说明和允许关闭。 |
| 到期 | 停止新的核心切换操作，但保留设置、账号、更新、帮助、订单和导出配置入口；若未来提供配置导出，其可用性不应因到期被收回。购买或续费后恢复原配置。 |
| 到期瞬间 | 不在已经开始的单次切换中途打断；从下一次唤出检查。首次展示“试用已结束/授权已到期”与购买入口，可关闭。随后继续可从菜单打开账号页，避免每次按键都变成支付弹窗。 |

不限制设备不等于无需账号安全：可提供登录记录和“退出某个会话/退出其他会话”，由用户管理被盗会话；不以设备数量触发封禁。

## 建议的离线规则

日常窗口切换完全在本机完成，不逐次联网鉴权。首次领取试用、首次同步购买、新设备登录和恢复账号需要联网。

建议首期每次成功联网校验后发放 **最长 7 天**的本地授权凭据，实际可用截止为：

`本地授权截止 = min(账号本次权益截止, 最近成功校验时间 + 7 天)`

- 7 天是本项目候选参数；试用和付费均不能因离线而越过原到期时间。
- 在线时在后台定期刷新；失败不会立即中断仍有效的本地授权，也不会因失败反复生成新的 7 天。
- 到达本地授权截止，但账号权益尚未到期，显示“请联网验证授权”，不能误称“请再次购买”。联网成功即可恢复。
- 重启、重装、修改系统时间不能由客户端自行延长服务端签发的截止日期；实现阶段需要专门设计时间回退与凭据校验。不能承诺纯离线环境下可完全防破解。
- 已到期、已撤销或退款导致的权益变化，在设备再次成功校验时同步。真正离线设备最多可能继续使用到现有凭据截止，首期接受这个有界延迟；不能同时承诺长期离线和退款瞬时全设备撤销。
- 客户端短暂断网和授权服务故障共用这一缓冲，不无限加时。长时间服务故障应有运营公告、补时或重新发放授权的可审计处理；不能每次重启自动补时。
- 账号退出后清除该账号的有效本地授权，但保留本机设置；重新登录同一账号可恢复剩余权益。

## 售后闭环的最小产品形态

官网账户中心建议保留四个清楚入口：**我的授权、订单与退款、下载与更新、帮助与工单**。App 的账号页显示相同的到期时间、最近校验状态、“同步购买”和联系客服入口。借鉴的是前述产品的可找回、可恢复形态，并不照搬其设备收费或许可模型。

| 用户情况 | 前台应提供的结果 | 后台需能查清的记录 |
| --- | --- | --- |
| 已付款，未开通 | 保留订单页，显示“付款确认中/开通处理中”，允许重新查询；不要让用户继续重复支付；超过处理时限能带订单号创建工单 | 商户订单、渠道交易、付款确认、权益发放分别有状态；服务端重查和补发须幂等 |
| 重装、换电脑或网页付费后回到 App | 同一账号登录后同步剩余授权；“同步购买”有明确结果，不要求重新购买 | 当前登录账号、权益来源订单、最新版本和校验结果 |
| 重复付款 | 区分用户有意买多个周期和实际重复支付；展示每笔订单及新增期限，允许申请核查/退款 | 每笔交易及对应授权区间，不能仅有一个可随意覆盖的到期字段 |
| 退款 | 订单详情发起申请，状态包括申请中、待补充、审核通过、渠道处理中、已退/失败、拒绝及理由；显示实际退款金额 | 原订单、退款原因/金额、渠道结果、权益调整、处理人和时间 |
| 切换失败、安装或更新失败 | 能直接到对应帮助文章或创建工单；技术问题不等同于“账号到期” | 用户自愿提供的 App/系统版本、错误码、订单号等最少信息；不自动附带窗口标题、屏幕内容或应用使用历史 |
| 更新及兼容性问题 | 账户到期仍可查更新说明、系统要求和下载；说明哪些版本可用；更新失败有重新下载和恢复配置路径 | 版本、分发包身份、兼容范围、已知问题与处理进度 |

建议首期客服采用一个公开客服邮箱/网页工单，关联订单和账号；先保证可受理、可追踪和状态通知，再考虑在线聊天。候选运营目标为 2 个工作日内首次回复，正式对外承诺前需要确认实际维护资源。

## 退款政策候选，不是现行承诺

建议讨论以下简单起点：**首笔购买付款后 7 天内可申请全额退款**；尚未开始的主动续期订单也可申请全额退款；重复扣费或确认的无法使用问题有独立处理路径。已经开始的续期订单，先按具体故障和订单事实人工处理，是否普遍按未使用时间退款需另行定稿。此处 7 天是自愿商业政策候选，不是在判断数字软件一律适用某条法定退货规则；正式条款需结合大陆销售规则和签约支付渠道核验。

退款申请中不应立刻删除所有授权。退款完成后，仅撤回对应订单授予的未使用权益，重算其余有效权益；不能把别的有效订单或全部账号设置一并删除。全额退款涉及已使用时间时，应按明示政策处理，不产生负余额或秘密追扣。跨多个预付周期的退款结果应在确认页展示新的可用截止时间。

## 后续验收用例与限制

进入实施前至少固化这些用例：同账号两台电脑共享试用结束时间；新设备不另起试用；试用中购买不丢余额；按键期间到期不打断已经发起的切换；断网 1 天仍可用但不越过权益结束；第 8 天要求校验而非重复付款；退款离线延迟符合告知；回调重复不多发权益；付款成功页丢失仍能找回订单；退款不撤销其他订单。

本次只查阅上述六个官方页面并编写本文，未购买竞品、未登录竞品账户、未实验其离线失效边界、未验证其未公开的计时防重置实现；没有把页面没有说明的行为当作事实。业务规则最终基线需在 owner 讨论后写入新的商业化 spec；当前 SPEC-001 仍是本地版行为契约。
