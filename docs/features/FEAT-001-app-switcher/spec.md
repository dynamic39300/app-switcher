# SPEC-001：App 切换器行为契约

上游：[PRD-001](prd.md)；设计：[DESIGN-001](design.md)；验证：[QA-001](test-plan.md)、[TRACE-001](traceability.md)。2026-09-24 按 owner 授权校准行为基线；accepted 表示产品意图已确定，不表示测试通过。

2026-09-25 商业化范围更新：本功能的窗口控制与本地隐私边界继续有效；早期“无账号/无网络”描述的是 0.3.2 基线。新商业构建的登录、授权与切换前门禁由 [FEAT-002](../FEAT-002-commercialization/spec.md) 定义，网络请求不包含窗口标题、使用统计或按键内容。

## 模式与目标

每次唤出默认**应用模式**：每个 `.regular`、非自身的运行进程一个入口，以 PID 区分同产品的不同进程。选择会请求该 App 按正常打开方式显示窗口并成为前台，由系统 / App 决定显示哪一个窗口；不把前台 PID 正确等同于窗口已经可见。后台 / 菜单栏进程排除；没有可枚举内容窗口的普通 App 仍保留入口。

应用入口在确认所选安装路径不存在另一潜在主应用实例时发起正常 reopen 请求，随后核对原 PID 与进程启动身份再移交前台。同一安装路径的辅助进程，只有在它与目标的可执行文件路径都已知且明确不同时，才不计入主应用实例；路径未知时保守保留。相同安装路径及相同可执行文件的多实例仍明确失败并提示选择具体窗口，不按 bundle ID 猜测重开对象；目标没有 `.app` bundle URL 时仅按精确 PID 激活，不保证恢复窗口。窗口恢复 / 创建取决于目标 App 的 reopen 行为，不承诺所有 App 都创建窗口，不通过 AX 批量恢复所有窗口。具体窗口目标继续使用原 AX 对象，不走 App reopen 路径。

Tab 切换到全局**窗口模式**。一个 App 的窗口集合只有在枚举完整、每个待展开窗口有可用控制对象、支持抬起及主窗口操作、且标题去除首尾空白后非空且不重复时才展开。扫描时已经最小化且 `AXMain` 不可写的窗口不尝试主动恢复探测，整个 App 保留应用入口；已入选的窗口随后最小化，激活时只恢复该目标再核对能力。任一条件不确定则整个 App 回退单一应用入口，明确标注只能切 App；无标题 / 同名窗口不生成数字条目。

窗口身份与展示标题分离；选择后只对快照中的目标对象操作，不以标题重新搜索对象，不按相同 bundle ID 选择首个进程，不批量恢复 / 抬起其他窗口。App 或对象消失、能力改变、无响应、权限失效、最终焦点不符都必须作为失败或无法确认反馈。

## 行为与状态

| 起始状态 / 触发 | 预期结果 | 失败、取消或恢复 |
| --- | --- | --- |
| 隐藏 → 当前唤出组合键（默认 `⌃⌥Space`）或已开启的 F→J | 当前活动屏显示 App 模式，固定这一轮键位快照 | 空集合给出「暂无可切换应用」说明 |
| 显示 → Tab | 切模式；窗口能力异步探测时呈现明确加载状态，已展示映射不被后台悄悄重排 | 慢 / 不支持的 App 回退单 App；再次 Tab 或取消使迟到结果失效 |
| 显示 → 有映射的物理键 / 点击键帽 | 发起一次目标激活，面板让出前台 | 无映射键无操作；激活中抑制重复提交 |
| 显示 → 方向键 / Enter | 在已分配目标间移动可见选择；Enter 激活当前选择 | 无候选时无操作，不激活空键 |
| 显示 → Esc / 外部点击 / 再按热键 | 收起并取消本轮探测；不执行目标切换 | Esc / 热键取消恢复合理前台；外部点击尊重用户点击后的前台 |
| App 激活完成 | 对唯一可定位实例请求正常窗口呈现，核对进程身份并移交前台；读回 PID 确认 App 级激活 | 请求或身份核对失败给中文反馈，不改投另一实例；PID 成功不代表窗口可见已验证；若用户已转到无关 App，不抢焦点，下次唤出时显示原因 |
| 窗口激活完成 | 读回目标 PID，且其 focused window 与所选 AX 对象一致后确认 | 不能确认则中文反馈，不自动重试别窗；若当前仍是本应用或目标 App，恢复 App 面板，否则保留消息待下次唤出 |
| App / 窗口集合变化 | 当前快照不重排；下一次唤出或切模式重算 | 旧 token 不得指向重建窗口；失效目标反馈后重新选择 |

覆盖层 UI 不编辑、关闭或移动用户窗口。窗口模式只显式恢复用户所选目标；应用模式通过正常 reopen 让目标 App 处理其窗口，避免批量 AX 恢复。跨 Space / 全屏遵循系统行为，不主动操作桌面。网络离线、限流、编辑草稿和账号登录状态不适用。

## 键位规则

- 集合：字母 `A–Z` 共 26 个，数字行 `1 2 3 4 5 6 7 8 9 0 - +` 共 12 个，合计 38。数字行只要有映射就必须完整可见；所有映射必须可按键触达。
- 以物理 QWERTY 键位解释选择；中文输入法下仍能选择，等号所在键对应界面 `+`。Shift 不改变目标；Cmd / Control / Option 修饰组合不误当普通选择键。
- rank 为组内最高使用次数降序 → 最近使用降序 → 稳定 App 身份 `groupID` 升序兜底；组内按标题再按候选身份排序。同输入产生相同映射；不承诺集合变化后的永久固定键位。
- 组首目标优先英文首字母；冲突时取最近空闲字母（QWERTY 距离，相同则 home row、靠左优先），再用剩余键。非英文字母名优先数字行，数字行满后使用空闲字母。
- 同 App 展开窗口使用组内顺序分配相邻可用键；标题变化不会改变控制身份。仅保留本次快照的顺序，不把短期 token 作为跨启动持久窗口身份。
- 超过 38 个目标按 rank 截断，显示有目标未列出的提示。

## 唤出快捷键设置

菜单栏「设置」和覆盖层齿轮进入同一个独立原生设置窗口；从覆盖层进入时结束该轮面板会话，避免选择键与录制争用。此设置只改变唤出方式，不改变面板内 38 键映射、排序或窗口激活行为。

| 状态 / 操作 | 契约 |
| --- | --- |
| 打开设置 | 展示当前保存值和 F→J 开关，编辑使用独立草稿；重复打开复用设置窗口 |
| 开始录制 | 仅在本设置窗口捕获。组合需包含 Command / Control / Option 至少一个，可叠加 Shift 和一个支持的普通键；单独修饰键、无修饰或仅 Shift 均不作为有效组合 |
| 录制与取消 | 录制期间暂停本工具全局组合键，以允许录制当前组合；F→J 使用独立暂停原因。Esc、失焦或关闭结束录制并恢复已保存绑定；失焦不提交草稿，关闭丢弃未保存草稿 |
| 保存 | 校验并注册新组合、原子保存本地配置后生效；成功反馈，重启保留组合键与 F→J 开关。重复提交不得注册多个绑定 |
| 无效 / 冲突 / 写入失败 | 中文说明关联输入，不清空合法草稿；新注册或持久化失败不丢旧绑定和保存值。检测已知系统保留 / 已启用系统组合及 Carbon 可检测的排他注册冲突；系统检查失败不继续提交。不能保证发现所有第三方非排他注册、事件监听或应用局部快捷键，注册成功不等于没有其他响应者 |
| 恢复默认 | 草稿恢复为 `⌃⌥Space`、F→J 开启；仍须保存，保存失败遵循相同回滚规则 |
| 启动时配置异常 | 缺失配置使用默认；损坏或无效配置明确提示并降级默认。有效的保存组合无法注册时报告不可用并保留菜单设置入口，不静默改成另一组合；默认不可用时同样明确反馈，不静默覆盖损坏文件 |

F→J 的空闲 / 序列时间及回放行为保持不变，本轮只增加开关，不允许自定义无修饰双字母。退出录制只移除录制暂停原因，不能误解除覆盖层等其他暂停原因。配置单独写入本地 `shortcuts.json`，不迁移或改写 `usage.json`，不写录制按键日志。

## 非功能与隐私

- App 覆盖层显示目标 ≤ 150ms，环境为本机 Apple Silicon / macOS 26；异步窗口发现耗时单独记录，不能以单元测试替代性能测量。
- AX 跨进程访问有短超时与有限探测预算；不在主线程做整个窗口枚举；App 不响应时及时保留 App 入口。
- 本地统计只持久化 App 身份、计数、时间戳；快捷键组合与 F→J 开关单独持久化。标题和 AX token 仅内存快照，收起 / 失效后释放；日志不包含标题或逐键输入。无屏幕内容、录屏请求、私有 API、网络请求。
- 支持 macOS 15+、Apple Silicon、中英文显示与 QWERTY 物理键。面板取本次活动屏 `visibleFrame` 宽 92% / 高 82%，至少留 16 pt 安全边缘并居中，取消 1080 pt 宽度上限；Tab 切模式不改变面板外框。键盘区域按 3 / 4 行分配可用高度，键帽至少 104 pt，短屏仅键盘区滚动；图标按键帽宽约68% / 高约52%的目标缩放，不设原64pt上限，并受名称/窗口说明与键标所需空间约束；名称与键标随键帽适度增大。候选保留可访问名称与可见选择；完整 VoiceOver、200% 放大未测前不宣称符合。

## 基线变更与历史边界

TKT-009 影响 AC-01 至 AC-08、AC-10，新增 AC-11 至 AC-13；当时 AC-09 未完成。2026-09-20 的 CG 过滤 / 多窗平铺与 2026-09-22 的数字排序属于历史实现；[RES-002](multi-window-research-2026-09-24.md) 已复现增删窗口造成编号漂移，并修正「Chromium 永不支持 AX」「所有标题必须录屏」「必须 Developer ID 才能授权」等过宽推论。当前契约以本文和 [ADR-0001](../../adr/0001-capability-based-window-switching.md) 为准，真实兼容结果以 QA 记录为准。

0.2.0 安装后用户反馈按 S 不能唤起 Spotify。TKT-010 将 AC-05 从单纯「前台 PID 正确」校准为「请求应用正常窗口呈现后激活原进程」；受影响的是 App 级路径及其回归，具体窗口、UI 和排序不变。隔离红证据已证明普通 `activate` 在最小化或关闭最后窗口时可报告成功但没有可见窗口，用户原始窗口状态尚未确认；见 QA-001 的 TKT-010 记录。

TKT-011 按用户后续要求放大面板、充分适配屏幕并去掉每个 App 下重复的「应用」字样，影响 AC-10 的布局与文案。应用模式不保留无意义副标题空行；窗口模式仍显示真实窗口标题和「应用入口」回退说明，可访问名称继续区分应用 / 窗口。激活、排序和权限范围不变。

TKT-006 按后续自定义快捷键要求补齐 AC-09，并回归 AC-01 的可配置唤出行为，版本 0.3.0 已实现并完成受影响本地验证，真实保存与重启注册已观察；人工余项以 QA-001 为准。

TKT-012 按用户要求进一步放大键帽图标，影响AC-10；窄短屏优先保留两行名称/窗口说明及独立键标，验证见QA-001。

TKT-013 针对用户报告选择微信后覆盖层重新显示的缺陷：现场诊断捕获同一 `WeChat.app` 下的 `WeChat` 主进程与 `wxplayer` 辅助进程被当作两个应用实例，reopen 在身份守卫处被拒绝。修复将可执行文件身份纳入歧义判断，影响 AC-05 / AC-07；保留真实多实例保护和回调 PID / 启动时间核对。该缺陷不能据此解释尚未复现的 WorkBuddy 失败；TKT-013 的该缺陷已在 0.3.2 修复并完成隔离回归及真实微信点击验证；具体证据与未覆盖范围见 TKT-013 / QA-001。
