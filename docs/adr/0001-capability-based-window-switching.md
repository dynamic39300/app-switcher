# 默认切 App，按窗口能力开放精确切换

旧版把 CG 清单中的每个窗口展开为「窗口 N」，再以显示标题查找 AX 对象，导致无标题、同名和编号变化时目标无法可靠对应；增加标题权限也不能修复身份连接。owner 在 2026-09-24 接受 [RES-002](../features/FEAT-001-app-switcher/multi-window-research-2026-09-24.md) 建议并授权系统修改，我们选择默认一运行进程一键、Tab 切换到全局窗口模式，只展开具有可用 AX 对象、支持抬起和主窗口操作且标题非空唯一的 App 窗口集合；任一不确定则整个 App 保留应用入口。

窗口身份采用公开 AX 对象的短期引用和不透明 token，标题仅用于内存中的辨认；只恢复目标窗口，操作后核对前台 PID 与 focused window。失败或不能确认时显示中文原因，不把 App 激活当作窗口成功。代价是部分 App 只能做 App 级切换，跨 Space、全屏与应用版本变化必须实测；收益是用户可见目标与实际承诺一致，不依赖录屏、私有桥接 API 或标题匹配。

放弃继续数字平铺及标题猜测，因为它们不能保证对应关系；不采用私有 CG ID→AX 桥接路线，因为本期优先公开接口和可解释的回退，避免扩大兼容维护与权限范围。本决策确定产品边界，不代表所有真实 App 的聚焦已验收；验证状态见 [QA-001](../features/FEAT-001-app-switcher/test-plan.md)。

2026-09-24 补充（TKT-010）：Spotify 唤起反馈及隔离复现说明，只有前台 PID 正确不能保证用户看到 App 窗口。App 入口改为对唯一可定位运行实例发送正常 reopen 请求、复核 PID / 启动身份后移交前台，窗口呈现交由目标 App；多实例歧义不重开任意对象，也不批量 AX 恢复。具体窗口仍按原 AX 对象执行，本 ADR 的能力门禁和精确窗口边界不变。API 依据与红 / 绿验证分别见设计及 QA-001。
